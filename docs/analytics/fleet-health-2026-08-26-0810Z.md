## Method notes (for the next analyst pass)

1. Always pass `&agentId=` for per-agent claims. The company-wide `?limit=500` sweep covers only
   ~10.7h here and *shrinks* as failure volume rises — it would have hidden the CEO's 145.8h gap
   entirely (its window starts 08-25T21:21Z).
2. Classify failures by `error` string before counting. Raw `failed` counts in this window are
   84% spend-limit noise and would have buried the 21 endpoint failures that actually matter now.
3. `status: "running"` on an agent record does not mean healthy — the CEO record carries
   `status: running` *and* `errorReason: Endpoint unreachable: fetch failed` simultaneously.
4. Exclude `queued`/`running` from success-rate denominators; the trailing partial hour reads as
   a false 0% otherwise.
